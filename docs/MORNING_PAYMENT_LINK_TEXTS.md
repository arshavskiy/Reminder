# טקסטים ללינקי תשלום בחשבונית ירוקה

> **לפני הפעלה — מה שהאפליקציה תומכת בו היום**
>
> הפרמטרים `plan` ו-`billing` נקלטים ונשמרים על המשתמש בהרשמה
> (`signup_intent_plan` / `signup_intent_billing`) — **למעקב בלבד**. הם אינם
> משדרגים את המנוי, ובכוונה: כל אחד יכול להקליד URL כזה בדפדפן.
>
> **השדרוג ותאריך התשלום חייבים להגיע מאישור תשלום מאומת**, דרך מסך הניהול
> או אינטגרציה שרת-לשרת. הנקודה הקיימת היא `POST /api/billing/tier`, מוגנת
> ב-`PAYMENT_TIER_UPDATE_SECRET`. עד שחיבור Morning מופעל, האישור ידני.
>
> `tab=register` פותח הרשמה למשתמש חדש; משתמש קיים יכול לעבור ללשונית כניסה.
> משתמש שכבר מחובר וחוזר עם `billing=one_time` מועבר למסך המנוי.

## הפעלת תזכורות לתשלום חד־פעמי

`billing=one_time` פירושו תשלום חד־פעמי מראש. כל יחידה של הפריט מייצגת חודש אחד, וניתן לקנות 1–12 יחידות באותה עסקה. פרמטר `months` מציין את מספר החודשים; בהיעדרו ברירת המחדל היא חודש אחד. `monthly` נשמר עבור חיוב חודשי אוטומטי, ו-`yearly` עבור תשלום שנתי. קישור החזרה אינו הוכחת תשלום ואינו מפעיל מנוי או דוחה תזכורת קיימת.

דוגמה לקישור חזרה לרכישת 12 חודשים מראש:

https://app.remindocr.com/login?tab=register&plan=basic&billing=one_time&months=12

אם Morning מחזירה אותו URL לכל כמות, אין להגדיר `months=12` לכל הלקוחות: יש למפות את כמות הפריט מהעסקה המאומתת לשדה `months` באישור התשלום, או להזין אותה ידנית במסך הניהול. הפרמטר בקישור נשמר רק ככוונת רכישה ולא גובר על הכמות בקבלה המאומתת. התמיכה באפליקציה אינה מגדירה את בחירת הכמות בממשק Morning.

לאחר בדיקת הקבלה ב-Morning, ניתן להזין את התשלום במסך Admin → Users → Settings → Record verified payment, כולל מסלול, סוג חיוב, מספר החודשים שנרכשו (Months purchased), מזהה תשלום ייחודי ותאריך התשלום בפועל. יש ליצור חשבון באפליקציה לפני רישום התשלום. משתמש קיים יכול להתחבר לחשבון שלו דרך אותו קישור חזרה.

לחלופין, אינטגרציה מאומתת יכולה לקרוא ל-`POST /api/billing/tier` עם הכותרת `x-payment-tier-secret` וגוף לדוגמה:

```json
{
  "email": "buyer@example.com",
  "plan": "basic",
  "billing": "one_time",
  "months": 12,
  "paymentId": "morning-receipt-123",
  "paidAt": "2026-09-20T09:00:00.000Z",
  "provider": "morning"
}
```

יש להעביר בכל חידוש מזהה חדש, את תאריך התשלום האמיתי ואת מספר החודשים שנרכשו. אישור כפול או ישן אינו משנה את מועד החידוש, גם אם נשלחה בו כמות אחרת. המועד מחושב כתאריך התשלום ועוד מספר החודשים הקלנדריים שנרכשו, ובסוף חודש מותאם ליום האחרון של חודש היעד. למשל, 12 חודשים ששולמו ב-20.09.2026 מסתיימים ב-20.09.2027; אין תזכורת אחרי החודש הראשון. אין חיוב אוטומטי ואין חסימת מנוי אוטומטית באיחור בתשלום.

תזכורת באפליקציה ואימייל אחד נשלחים כשהמועד מגיע. כשל בשליחת אימייל מאפשר ניסיון נוסף כעבור שעה. שליחת האימייל דורשת scheduler פעיל בסביבת production והגדרות SMTP/Resend תקינות; בדיקת ההתראות באפליקציה מציגה תזכורת גם ללא scheduler. תשלום חדש מאומת מתחיל תקופה חדשה. מעבר מאומת ל-`monthly` או `yearly` מפסיק את תזכורות התשלום החד־פעמי.

את לינקי התשלום החוזרים לשימוש מ-Morning יש להגדיר בשרת כ-`PAYMENT_LINK_DIGITAL_ONE_TIME` (ברירת מחדל `https://mrng.to/SUPCi1tsrC`), `PAYMENT_LINK_BASIC_ONE_TIME` (ברירת מחדל `https://mrng.to/5vjboMGOmm`) ו-`PAYMENT_LINK_BUSINESS_ONE_TIME` (ברירת מחדל `https://mrng.to/qE6K86XDbW`). בלעדיהם מוצג כפתור לפנייה לתמיכה בוואטסאפ לקבלת לינק. הודעת האימייל מפנה למסך המנוי באפליקציה, שבו מופיע כפתור התשלום.

זו תשתית לחיבור תשלום מאומת, ולא חיבור webhook אוטומטי ישיר ל-Morning. עד לחיבור ואימות האירועים, אישור התשלום מתבצע במסך הניהול.
