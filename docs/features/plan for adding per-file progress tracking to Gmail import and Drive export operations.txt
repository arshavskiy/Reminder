Design an implementation plan for adding per-file progress tracking to Gmail import and Drive export operations, reusing the existing upload/rescan progress modal pattern.

Background

The app has an existing "תוצאות העלאה" (upload results) progress modal in UploadModal.vue that shows per-file status cards with progress bar, summary stats, and clickable rows. It uses a 3-layer architecture:

Pinia store (client/src/stores/rescanModal.ts) — holds session state with start(), updateRows(), setRemaining(), markDone(). Has a kind field currently typed as "rescan" | "upload".
Orchestrator (in DocumentsPage.vue) — starts sessions, runs polling via startBatchPolling() (3s interval, fetches documents, filters to tracked IDs, counts remaining), feeds data into store.
Presenter (UploadModal.vue) — reads rescan state via prop, renders progress bar, stat grid (4 stats), and per-file cards with status badges. Uses isUploadSession computed (kind === "upload") to switch Hebrew labels.
Current flows that need progress UI:

Gmail import (handleGmailImport in DocumentsPage.vue):

Currently calls api.gmail.importAll() which returns { imported: number, results: [{ messageId, filename, documentId?, error? }] } synchronously
Creates documents in DB, then returns all results at once
Already has per-file results in the response, just not shown in a modal

Drive export (handleDriveExport in DocumentsPage.vue, also InvoicesPage.vue):

Currently calls api.drive.exportAll() which returns { ok, uploaded, failed, total } — only aggregate counts
Server endpoint loops through docs sequentially, uploading each
No per-file results returned
Key constraints:
UploadModal.vue is only used in DocumentsPage.vue, not InvoicesPage.vue
InvoicesPage.vue also has Drive export and Gmail import buttons
The rescan modal store is global (Pinia), so can be shared
Gmail import returns all results at once (no real-time polling needed — just display results)
Drive export is synchronous server-side loop — could be made async with polling, or kept synchronous with results returned at end

Implementation Plan: Per-File Progress Tracking for Gmail Import and Drive Export
Architecture Decision

Create a new standalone ProgressResultsModal.vue component extracted from the rescan tab of UploadModal.vue. This is the right approach because:

InvoicesPage needs it but does not use UploadModal at all
The rescan tab in UploadModal is already conceptually independent (no shared state with the upload/extract tabs)
The Pinia store is already global and can be shared across pages

      failed++;

    failed++;
  }
}
